# Downloads Stack + SmartExplorer — выжимка для отдельного проекта

Дата: 31 октября 2026. Статус: направление выбрано для следующего этапа; исходники установленной у пользователя копии и её точный локальный путь ещё не получены. Этот файл — задание на будущий форк, а не отчёт о готовой интеграции.

## Зачем это делать

Пользователю нравится установленный Downloads Stack как приложение в трее и его окно настроек. Вместо отдельного SmartExplorer в трее предлагается развивать одну программу: сохранить список загрузок и добавить команду открытия пути из буфера обмена. Это уберёт второй фоновый процесс и даст единое место для настроек и будущих команд.

Вывод после просмотра исходника: технически это удобная основа. Приложение уже использует WPF, имеет службу трея, настройки, слой вызовов Windows и тесты. Добавлять новую функцию следует как часть его собственного кода. Наш отдельный WinForms-прототип нужен только как описание работающей логики, не как встраиваемый `.exe`.

## Функция, которую переносим первой

`Win+Shift+E` обрабатывается самим приложением, без PowerToys. При нажатии:

1. Если в буфере один скопированный файл — открыть его папку и выделить файл; если одна папка — открыть её.
2. Если в буфере текст с существующим полным путём к файлу или папке — действовать так же.
3. Если в буфере другое содержимое — использовать последний корректный путь, сохранённый локально. Перед открытием повторно проверять существование пути.
4. Если сохранённого пути нет или он устарел — открыть обычный Проводник.

Буфер не изменять. Клавишу регистрировать на время работы приложения и освобождать при выходе. Если сочетание занято, показать понятную ошибку в настройках и сохранить работоспособность основной функции Downloads Stack. Не запускать вторую копию приложения. Существующее `Win+E` оставить Windows.

После первой функции можно добавить в настройки другие горячие клавиши и действия пользователя. Это следующий этап: пока набор команд, форма настройки и формат их хранения не согласованы. Черновой отдельный прототип показывает возможный список действий, но не задаёт окончательный интерфейс форка.

## Где искать точки интеграции

- [App.xaml.cs](https://github.com/Vivoxti/Downloads-Stack-For-Windows-Tray/blob/main/src/DownloadsStack/App.xaml.cs) — запуск и остановка служб, один экземпляр приложения.
- [TrayService.cs](https://github.com/Vivoxti/Downloads-Stack-For-Windows-Tray/blob/main/src/DownloadsStack/Services/TrayService.cs) — существующее скрытое окно для сообщений Windows и значки трея; проверить, можно ли использовать его HWND для `RegisterHotKey`/`WM_HOTKEY` без второго окна.
- [SettingsStore.cs](https://github.com/Vivoxti/Downloads-Stack-For-Windows-Tray/blob/main/src/DownloadsStack/Services/SettingsStore.cs), модели настроек и `SettingsWindow.xaml` — хранение и показ будущих команд. При расширении JSON предусмотреть чтение старых настроек.
- [ShellService.cs](https://github.com/Vivoxti/Downloads-Stack-For-Windows-Tray/blob/main/src/DownloadsStack/Services/ShellService.cs) и `Interop/NativeMethods.cs` — открытия путей и вызовы Shell. Для выделения файла предпочесть `SHOpenFolderAndSelectItems`, проверив текущую реализацию, вместо сборки командной строки с путём.
- `src/DownloadsStack/Assets` и проектный файл — все варианты новой иконки; `tests/DownloadsStack.Tests` — проверки путей, буфера, fallback и конфликтов клавиш.

В отдельном форке проверить и развести с установленным оригиналом идентификаторы приложения, механизм одного экземпляра, автозапуск, ярлыки и папку настроек. Иначе две программы могут мешать друг другу или читать одни данные. Не менять и не удалять установленный Downloads Stack ради прототипа.

## Перед началом кодирования

1. Получить от пользователя путь к локальному исходнику/установленной сборке и определить, совпадает ли она с публичным релизом. Сверить `git status`, версию и локальные изменения до начала правок.
2. Создать отдельную копию или Git-форк исходника с сохранённым `LICENSE` и зафиксированным upstream-коммитом. Сохранить оригинальную установку отдельно.
3. Реализовать первую функцию и проверить обычные файлы, папки, UNC-пути, пробелы/кириллицу, занятое сочетание, пустой буфер и удалённый сохранённый путь. Затем проверить вручную запуск из трея и автозапуск.
4. Нарисовать новую иконку; пользователь планирует сделать её в Figma и передать SVG. Черновой рисунок рядом — только временный ориентир.
